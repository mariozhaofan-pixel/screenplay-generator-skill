# 编剧与导演的双向交接

scope: 导演送来的格式整理/修改意见/授权补足，以及用户请求视频模型提示词时转交独立导演Skill。这里维护边界与回传接口，不复制对方协议。

## 先锁当前交接

在项目接续或交接记录中保存：来源技能、返回目标、模式、当前源稿路径与版本、本次集/场/原句范围、保护项和未决问题；已有等价记录直接沿用。源稿不是当前采用版时先定位正确文件，不凭摘要猜正文。只读授权范围与必要衔接，不把交接升级为全剧开发。

默认保护原台词逐字文本、人物身份与关系、事件、因果、发生顺序和结局；模式本身不授权改变这些内容。收到带返回目标的交接后完成对应编剧职责并回传结果与剩余问题，不自动推荐回原技能、不再次发起同一交接，也不把他方建议当作用户改稿授权。交接记录留在制作资料，不混入正式场景或模型提示词。

## 导演到编剧

| 模式 | 实际工作与交付 |
| --- | --- |
| `format-only` | 读取[标准剧本格式](screenplay-format.md)，只整理明确可识别的场头、段落、△动作标记、角色与对白的分行及排版。保留原句措辞、对白标点、事实和顺序；场号已有则保留，缺少的编号只能按既有明确场界补齐。人物、地点、日夜、内外、声源/OS归属不明确时保留原文并记录缺项，不编造。保存获准范围的格式整理稿.md，原稿先留备份或按用户要求另存；不补写梗概、小传、后续节奏或缺失剧情。 |
| `notes-only` | 只交 `修改意见.md`，逐项写位置/原句、具体问题、依据、影响与最小建议；区分格式、真实语义歧义和可选创作建议。建议涉及原台词/人物/因果/顺序/结局时明确需要的授权，未经授权不回写源稿、不把改后整稿夹在附件。 |
| `rewrite-authorized` | 只对用户明确授权的剧情、动作或对白层作窄修；读取当前问题确需的方法，沿入口“剧本窄修”保留无关正文。交接必须说明哪些保护项允许变化，其余继续冻结。只有收到明确结构修改授权时才重排对应范围，不重做全稿练习。 |

格式不规范但可读时，整理只是可选服务：用户未选就不改源稿，导演可以继续使用原稿。梗概、事件列表或粗略创意不因缺少场头而被判错。只有确实影响执行的说话者、指代、因果或结局歧义才请求具体澄清；独立可处理部分继续完成。用户只要建议，最终产物始终是意见文件。

交付前只核实际差异和本次保护项：`format-only`检查排版改变没有改写正文语义或逐字对白，`notes-only`确认源稿未改；窄修只检查受影响因果与衔接。普通剧本/格式稿/意见文件不运行 `scripts/validate_output.py` 的分镜模式；该脚本仍只服务其既有问答和明确分镜合同。正文继续遵守本Skill当前批次限制，不因交接一次输出额外集数。

## 编剧到导演

触发条件是用户要Seedance或其他视频模型的可执行生成提示词，或当前任务明确授权“剧本完成后继续编译视频提示词”。仅要求标准场景剧本、文学修改、创作建议或本Skill的明确分镜稿时，不自动切换。

1. 从宿主技能目录定位独立 `director-seedance-prompt`。同级安装时可检查相对本Skill根目录的 `../director-seedance-prompt/SKILL.md`，但实际路径由技能发现确认，不能依赖作者电脑的绝对目录。它是条件触发的外部依赖，不随本包复制。
2. 实际读取对方 `SKILL.md` 与其当前任务必需文件，完整执行其版本/规则来源、输入路由、资产、生成提示词及检查流程；不凭本文摘要或记忆伪装调用，也不把本Skill分镜格式直接当成导演输出格式。
3. 交接当前采用稿及真实路径/版本、授权范围、逐字对白与其他保护项、已有资产/参考和规则文件、未决问题、已知目标模型/版本/时长。未知参数留给导演入口解析；不重复询问已确定的选择。源剧本与视频提示词分开保存。
4. 若这是导演先前送来的格式或意见任务，先把本次结果按原返回目标交回即结束本职，不另建新的导演任务或自行再跑一轮编译。是否继续视频编译由原任务已有授权决定；交回不等于授权发送消息到别的聊天。
5. 找不到或无法读取外部Skill时，说明“导演Skill当前不可调用”及实际缺口；可完成已授权的剧本/意见部分，不声称已经协作或交付已验证的视频提示词。不为了这个接口复制外部Skill正文、书库或工具。

回传只包含真实完成的文件、对应模式与范围、保护项差异和仍待解决的问题；生成/交付/验收状态分别记录。双方各保留自身职责的单一权威，当前用户要求始终优先。
