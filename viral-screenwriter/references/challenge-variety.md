# 挑战综艺模块

## 适用与优先级

仅在用户明确要挑战综艺/AI挑战节目，或参赛者围绕可执行玩法、胜负/淘汰/资源进程构成观看主线时加载。挑战自我、恋爱困难、比赛只是人物故事背景，不切换模式。混合题材可只借用比赛段的规则可视化，不改主叙事合同。

用户锁定项与保真转换优先；已有稿窄修先走 SKILL 开头快路，沿用基线模式，纯摄影、表演或原创对白修改不打开本模块、不补模式标记。只有玩法或状态依赖缺口需要本模块时才取对应小节。本模块辅助 [Coffee Break 主编译链](coffee-break-method.md)，不是该书原法、新增的31样本统计结论或每日 active 规则。默认仍写标准格式剧本，每次最多2集。

挑战模式用“观看焦点、挑战契约、升级与最终兑现”替代通用流程的单一主角欲望、不可逆代价和高潮二选一要求；人物因果、清楚承诺和真实后果仍须成立。不强制个人成长、牺牲、价值两难、反转或下集悬念。用户已锁的代价与结局必须兑现；选择了反转仍须至少两处可回看证据。其他题材继续使用通用要求。

## 观看焦点与挑战契约

先沿用已给信息；模型或子代理把未决玩法开发成成熟答案。用户希望共同开发且玩法存在重大分岔时，才通过[共创协议](soul-questioning.md)让用户选择；普通玩法细节内部完成，用户要一稿时可合理暂定。以下焦点供内部建模，不能只把三个抽象类别扔给用户：

- 群体淘汰：观众追踪整体进度、幸存策略与规模变化；群体必须有可见行动，不能只作背景数字。
- 群像选手：追踪具有可辨识策略、关系和位置的若干选手；焦点交接由同一事件或资源连接，不轮流报人物小传。
- 单一主角：围绕一名选手的目标与策略组织其他参赛者；无需默认添加牺牲或成长线。

在后台厘清六项契约：`参赛资格与初始人数/队伍｜有效行动及判定｜时间/空间/工具限制｜出局与复活条件｜胜负与奖励｜失败后果`。没有淘汰或奖励就记录实际积分、名次、资源或挑战结果，不能用空泛“失败了”代替后果。正文通过行动、对白或必要字幕表现相关规则，不附契约表。

契约完整不等于开场口播全部读完。首次有效尝试用画面证明关键规则：行动前可辨条件 → 行动 → 可见判定 → 结果反应。尚未生效的细则可在需要时揭示，但决定胜负的资格、复活或道具能力须预先埋证，不能临时救场。

## 先开发与审计，按需共创

模型或子代理从用户火种、人物行动及既有规则出发，按[练习编排](exercise-orchestration.md)选择能解决当前缺口的练习并实际作答；自查或从最终胜负逆向核对规则、策略、计数与证据。用户希望共同开发且有重大分岔时，筛成2—3套有依据的成熟答案，每套说清具体行动、升级和兑现，按[共创协议](soul-questioning.md)供选择、换一批、自定义或组合，不交空白开放题。普通细节内部决定；“帮我写/给一稿”可在限制内合理暂定并完成稿件。已选契约直接继承；已明确等待某项选择时不能把沉默当选中，已有稿窄修不重开。来源未知的玩法工具只能标为辅助改编，不伪称Coffee Break练习；不必让角色受害或牺牲。

用户要求换方向时，可比较`主玩法｜参赛关系/观看焦点｜升级变量｜胜负兑现`，找出真正改变故事的未锁维度；不能只换道具名称或场地皮肤，也不为凑差异数量重开合同。沿用原授权边界，沉默不是确认。

后台开发记录可采用以下简记；共创时从中提炼足以判断2—3个成熟答案的具体依据，不让用户盲选。最终标准剧本不追加方向确认摘要或模式标记：

```markdown
- 创作模式：挑战综艺
- 观看焦点与目标：群体淘汰／群像选手／单一主角，实际选一类并写清目标。
- 挑战契约：【参赛】具体参赛条件；【机制】有效行动与判定；【限制】实际边界；【出局】具体判定或无淘汰；【胜负奖励】胜负标准与奖励或明确无奖励；【失败后果】具体影响。
- 升级与最终兑现：由哪次结果触发何种新压力，结尾如何判定并兑现开头承诺。
```

采用状态如实记录确认原话或直接输出授权，不虚构确认。无标记的旧稿不自动迁移格式。

## 从玩法到场景

按需要循环“承诺与证明 → 尝试与策略分化 → 可读结果 → 结果触发升级 → 最终兑现”。不固定4/6/8段，不另设总时长或强制百分比分段。沿用前三秒承诺、前20%首次局部兑现及静默密度预算，规则读数和人物反应保留可读时间。默认写场景行动与对白，明确完整逐镜时才设计并输出镜头。

每轮选一个观众能复述的主升级变量，其连带后果可以同时影响时间、资源和关系；不能为单变量原则切断因果，也不能同时换一套全新玩法。可选发动机：资源越多越暴露位置、领先者承担新的限制、落后者通过已公布条件获得不同策略、合作资源与个人排名相冲突。它们是原创候选，不是强制桥段。

例如：搬运灯的队伍越快接近终点，灯光越暴露路线 → 对手调整拦截 → 领先队选择遮光减速或继续抢跑。升级来自已有规则的后果，不是主持人临时宣布新能力。

每个阶段应有行动、规则证据或结果职责；航拍证明规模与边界，特写证明判定，反应镜改变站队或策略理解。人数大不等于每镜必须出现所有人。人物、地图、号码、服装或道具锚点用于保持焦点可辨，不硬性规定主角人数、写实媒介或画幅。

## 数字状态与窄修

仅对片中实际反复使用的计数，在后台简记：`项目｜变化前｜事件｜变化后｜对应集-场`，已有逐镜稿可沿用CUT。没有反复数字就不建表，不把状态账本塞进标准剧本。区分在场人数、本轮出局、累计出局、复活、资源与积分；不同口径不得混叫“剩余”。

人数按 `新在场 = 原在场 + 入场/复活 − 本次出局/离场` 更新，例如10人在场、3人出局、1人复活后为8人；累计出局事件数不会因复活自动减1。只在剧情确实需要时分别记录人数和事件数。一次事件跨多镜只记一次，画面、字幕和口播使用同一事件后的状态。

标准剧本把阶段变化写入△动作、对白与必要字幕；仅明确完整逐镜或修订已有逐镜稿时，才写入“调度（IN/CHANGE/OUT）”“台词/旁白/屏幕文字”“钩子职责与回收”，沿用H-ID，不加第12个CUT父字段。数字修改只定位该项的前态、事件及实际受影响后续引用；若必须越过获准集-场、原句或逐镜字段范围，先说明最小扩围，不借机通读或重写全稿。纯摄影窄修无需读取状态表。

## 查证与结束

原创玩法和片内算术不因本模块额外联网。新创作仍遵循研究协议；具体当期梗/IP、真实节目规则、原话、新闻、品牌事实按需查证，窄修只查受影响条目。品牌仅在用户brief需要时进入资源、工具或胜负因果，不固定出场时点，不虚构产品能力。

模型或子代理在自查/逆向节拍审计中判断：观众能否看懂规则与当前状态；每次升级是否有前因且数字自洽；最终结果是否兑现已选契约。必要的共创选择只交检查后的成熟答案；成稿请求直接在其授权范围内完成正文，普通细节不另设审批。无反转则用胜负兑现，无续集就完整收束；有自然策略分歧则保留，不为评论指标制造争议，也不在正文解释未采用的技巧。不默认附评分表或重复规格书。默认300秒、100 CUT/ceil(时长/3)仅为静默内部可剪辑容量与密度预算，不是可见镜数硬下限；无需先写100个完整镜头，不声称未实际设计的镜头已验证。每次最多2集，11字段仅用于明确完整逐镜，已有稿沿用同文件定点修订且不重开共创。
