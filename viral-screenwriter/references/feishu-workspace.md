# 编剧的飞书剧本工作区

仅在用户选择飞书协作、继承飞书项目或要求同步时读取。负责决定哪些编剧产物可发布以及如何回到创作任务；表结构、部署命令和同步算法沿下列共享合同执行，不在本文件另定一套。

## 资料路由

| 当前需要 | 读取资料 |
| --- | --- |
| 尚无可用环境、登录失效、连接已有库或创建新库 | [配置与授权](FEISHU_WORKSPACE_SETUP.md) |
| 新建/补齐四表、映射现有字段、查看附件与关联约定 | [四表布局](FEISHU_BASE_LAYOUT.md)与[JSON蓝图](../assets/feishu-base-blueprint.json) |
| 定稿/采用改稿发布、拉取云端剧本、跨设备冲突或失败恢复 | [剧本同步合同](FEISHU_SCREENPLAY_SYNC.md) |
| 导演送来的格式整理/意见/改稿或继续视频编译 | [编剧与导演交接](director-handoff.md) |

`scripts/plan_feishu_sync.py` 只生成本地增量计划，不联网、不替用户授权，也不证明云端写入完成。先查其当前 `--help` 与共享合同，以真实本地文件、云端快照和上次同步状态生成计划；实际读写使用宿主已连接工具或独立部署的官方CLI。本Skill内不安装飞书Skill、CLI、node_modules或凭据。

## 开始与接续

1. 优先读取当前项目已有的工作区选择。首次才询问本地、加入已有库或新建库；加入时接收对应多维表链接及已有分享密码，实际API身份与权限按配置指引验证。告知首次部署和授权增加启动时间，之后同一库可跨设备复用资料。用户未完成选择或授权时先保留本地工作，不猜建目标。
2. 采用与导演共用的 `.production/workspace.json`、`.production/sync-state.json`，只写在实际用户项目中；兼容旧 `.director/` 的迁移与冲突检查按共享合同执行。沿用同一 Base、项目ID、表字段映射和已有同步基线，不因为切换Skill或设备新建项目身份。分享密码与认证秘密保存在宿主安全配置中，不写普通JSON、接续、剧本或云端字段。
3. 目标已有剧本时先核对项目 `当前剧本` 中本次批次的采用修订，下载精确附件后检查本地状态，再编剧或窄修；只需要当前批及必要衔接，不拉取整个书库、所有视频或所有剧本进上下文。本地未改而云端已更新则采用新基线；两端均有变化按共享合同保留冲突，先不覆盖。
4. 四表为 `项目总览`、`资产库`、`段落交付`、`剧本交付`。在已有导演资产库上增补剧本表及关联，复用资产/段落的原记录和附件。`剧本md文件`承载真实Markdown附件；项目的 `当前剧本` 保留各批当前采用修订，段落的 `来源剧本` 保留实际编译依据，不能用所有历史修订或最新两集代替这些关联。

新建库默认启用密码分享与链接可编辑，已有密码沿用；明确的用户限制覆盖默认。选择飞书且已明确项目与接入范围，包含该项目定稿和后续采用改稿的例行上传授权；不为每次同步重复问“是否上传”。配置工具本身要求用户完成的登录或授权仍按实际流程执行。

## 编剧产物何时发布

- 用户已授权定稿交付，或要求在当前采用稿上落实改动并更新主稿：完成本次范围的检查、保存完整对应批次 `.md` 与接续后，自动按[剧本同步合同](FEISHU_SCREENPLAY_SYNC.md)发布到原 Base。已明确采用的方案无需再等一轮“确认定稿”。
- “给一版”“试稿”“提供建议”等探索请求保留为候选；`notes-only`只交意见。格式整理或替换段授权只覆盖该产物，不自动将其升级为当前采用的完整剧本。用户明确采用格式稿，或授权将替换段合入正确完整基线后，再发布完整修订。
- 每批沿用稳定剧本ID，新版使用独立修订，上传和读回确认后才更新本批的当前采用关联，其他批次保留。相同内容也须区分附件已同步与版本已采用；状态和关联的完成条件以共享合同为准。
- 正文始终遵守入口每次最多2集。本次改稿即使只改一场，上传的是该批完整采用稿；不把其他批次合成新大文件来规避批次限制，也不把云端旧批次删除或失去当前入口。
- 剧本新修订不自动重编导演提示词。仅记录实际受影响段落需复核，交接精确新修订与本次变更；既有段落记录、绑定资产和用户上传视频保留。

## 交付反馈

先交真实本地剧本文件和本次范围，再报告云端实际状态：目标Base、对应批次/修订以及“已上传并读回”“待同步”或“冲突待处理”。上传结果不明先读回核实，避免重复追加附件；同步失败保留本地成果和待处理项，不阻塞不依赖云端的创作，也不把本地计划说成同步完成。

实际剧本和接续不混入部署过程、鉴权内容或API响应。只向项目对应字段同步已授权的制作产物，书库、练习内部记录、认证二维码与临时缓存留在本地。
