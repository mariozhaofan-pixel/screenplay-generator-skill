# 共创协议：模型做题，用户掌舵

## 选择是工具，不是固定考试

目标是从简单想法共同做出值得继续看的剧本。Coffee Break练习由模型或子智能体完成，不能把空白原题交给用户。灵魂拷问保留为可选交互：人物立场、核心关系、结局或整体风格存在明显分岔时才给成熟方案选择。普通情节连接、措辞、节奏修复和检查由模型完成，不为每章、每道练习或每轮回复设置审批。

先判断用户当前意图：

- 只有种子、想一起开发：先做最相关练习，给一个推荐方案和一个有实质差异的备选，用具体行为或场景/对白小样让用户判断；先推进最影响全剧的一个决定。
- “帮我写/给一版/直接写”：在明确限制内采用可修改的创作假设，完成所请求稿件，不强迫先答选择题。必需的真实经历或制作事实不能捏造。
- 已有设定或大纲：复用已解决决定，只处理真实缺口。若已明确正在等待用户选择某重大分岔，不能把沉默当选中。
- “一步步/灵魂拷问”：使用下方选择轮；“你来定/不用问”：不增加常规选择轮。
- 窄修：冻结其余正文，不重启开发。“继续”：依上轮约定接下一部分，正文每次最多2集。

## 有必要选择时

1. 读取当前练习卡、种子和已采用状态，内部实际作答、筛选。
2. 从行动、回应与后果检查因果，保留2—3个真正不同、能成立的答案。“更燃/更虐”不算具体答案，不凑选项。
3. 一轮聚焦一个关键决定，给推荐和简短取舍。人物质感或对白问题给能判断的小样，少讲理论。
4. 用户可选、改一个点、换一批、自定义或组合。已选直接推进，不再问是否确认。组合先检查因果与结局是否兼容。
5. 采用结果成为下一层输入。选择只作用于已展示对象，不把“选A”扩大为所有未来细节永久锁定。

可用结构（不必显示“灵魂拷问”标题或教材术语）：

```markdown
这次最影响故事的是……
还需决定：一个具体的问题？

- 选项A｜具体行动（推荐）：谁做什么、对方如何回应、导致什么。取舍：……
- 选项B｜另一具体行动：完整答案及其后果。取舍：……

我推荐A，因为……
可以选A/B、换一批，或自定义/组合。选定后我会……
```

来源在内部练习记录定位；用户问方法时再解释。已有方向或没有实质分歧时直接继续，不强行造两个方案。缺少必需事实时只问最小资料问题，同时推进不依赖答案的部分。

## 状态与停止点

区分用户事实、用户已选、模型暂定、探索候选、明确锁定。原创推演不能记成用户事实或原书答案。备选围绕同一素材与世界，不每轮换题材。

保留当前观看承诺、人物矛盾、采用方向、未决分岔、已交集/场和下一步。完整练习答卷存文件，主上下文只留结果与定位，不重复读全书或淘汰方案。

选择轮交经过检查的答案后等待该项选择；成稿轮交足所请求的最多2集。多个备选不能拼出超过2集的正文。默认成稿采用[完整项目交付格式](screenplay-format.md)，含五项实写项目材料和当前正文；人物小传、后续节奏属于交付，方法、练习账本、评分和选择记录仍不混入成品。交完本批保存接续记录，等待用户继续，不把全剧藏入附件。
