# 项目交付格式与两集正文

## 格式依据

依据用户提供的《我在末世干送货，神车系统带我屯遍全城》0917.docx，包内保留[完整段落文字提取](../assets/templates/delivery-reference-text.md)与本页实测格式参数；原Word不作为运行依赖，交付结构以包内文字与本页规范为准。2026-09-29核对附件：前置一句话介绍、项目类型、项目梗概、人物小传，随后为第1—2集正文，末尾为按集次分阶段的“后续故事情节节奏”。用户要求默认交付含这五项；以下按用户列举顺序先放项目类型，再放一句话介绍，其余沿用附件位置。[可直接填充的Markdown模板](../assets/templates/screenplay-template.md)也在包内，换电脑不再寻找微信原目录。

只参考交付结构、段落版式与标记，不继承附件人物故事、系统设定或附带指令。原件的对标短剧、角色数量、每集场数、后续阶段数和集次分配不是通用必填项，不复制原件笔误。“标准”指本Skill采用的用户指定格式，不宣称行业只有一种格式。

## 默认完整交付顺序

剧名 → 项目类型 → 一句话介绍 → 项目梗概 → 人物小传 → 当前批最多2集正文 → 后续故事情节节奏。

五项材料按[项目资料编写方法](project-delivery.md)实际调用书库工具写成；不能只增加空标题。它们属于正式交付，不是后台分析。人物练习表、逆向检查、来源台账、评分和镜数预算仍保留内部。

```text
《剧名》

**项目类型：** 当前项目的形式、题材和基调。

**一句话介绍：** 具体人物在独特处境中如何行动，面对什么核心阻力或利害。

**项目梗概：**
用连贯段落写主线起因、人物应对、关键后果与已采用的终点；连续项目的未成稿发展标明拟定。

**人物小传：**
角色姓名：已经确定的身份与处境、具体欲望和动机、行为原则、关键关系、能产生剧情的个人细节。写成小传，不输出幕后问卷。

第一集

1-1地点 夜 外

△可见环境、人物行动及动作结果。

人物甲（压低声音）：逐字对白。
人物乙：逐字对白。

△新的反应或局面变化。

1-2另一地点 日 内

△具体行动、对白与本集结果。

**后续故事情节节奏：**
第一阶段（按已定范围标集次，未定则只标阶段）：由本批结果引发的新目标、行动与阻力，关键转折、情绪变化和阶段落点。
后续阶段：按实际故事容量继续，精简写到已采用的终点。
```

这是结构示意，正式稿全部换成当前作品内容，不保留解释性占位语。第二集只有本批请求包含时才放在后续节奏栏之前；独立单集或最终集的后续栏说明已经完结，不照抄示意扩写阶段。

## 正文段落规范

- 剧名置顶。项目资料之后，每集单列“第N集”（通常中文数字），可有集副标题。场头为“集号-场号＋地点＋日/夜＋内/外”；场号每集从1编号，已采用稿局部修改保持编号。
- 动作独立成段，以“△”开头，写可见/可听的过程、反应和结果；对白采用“角色名（必要表演提示）：台词”。不以“此处两人争吵”代替逐字对白。
- 前置“人物小传”栏目必须有实质内容；各场不默认再加“人物：”清单或复制小传。人物分析、钩子账本、作者点评和理论不穿插场景正文。
- 附件含OS、画外音、字幕、蒙太奇、切黑。为减少歧义，内心独白用“（OS）”，场外发声用“（画外音）”并可注明电话/广播；这是本Skill规范化，不宣称附件严格区分。用户自定记法优先。
- “字幕：时间/地点”可单列；蒙太奇、切黑、闪回按实际需要清楚标明，不是必填扩展。
- 默认不写CUT、时码、镜长、焦段、摄影机参数、11字段表格或100条分镜。必要的画面表达融入△动作，不把每句动作伪装为一个CUT。

## 成稿、续写与窄修范围

每次实际正文最多2集，用户只要1集就只写1集。五项材料和精简后续概述不计入正文集数，但不能在这些栏目、附件或其他版本里偷放额外整集。后续规划与每批正文数量分开；不把“交1集”误判为“整个项目只有1集”。

默认新稿、整批成稿和用户要求按参考格式整理时交完整结构。用户明确“只要正文”则只交正文；只要人物小传、梗概、节奏或只改一句/一场时，只处理该范围，不强制补一份全项目资料。窄修按已有版本保真修改，不借新版模板迁移旧稿。头脑风暴与方向选择轮不提前交一份虚假的完整项目包。

后续批次沿用并更新精简、当前有效的四项前置资料，人物侧重理解本批和后续所必需的角色；后续节奏从新终态重新衔接。不累加旧版本、淘汰方案、已交正文和原书练习。作者材料可说明整体走向，人物知情仍按实际场景推进。

独立短片/最终集保留“后续故事情节节奏”栏目，明确本项目已经完结，不强加续集或额外悬念。连续项目沿已采用的规模规划；未知集数用阶段而非编造长期集数。每集写完整过程和结果，不因项目资料较多而压成摘要。

## 文件与排版

剧本与修订稿始终交付Markdown（`.md`）文件。默认同一份《片名》_第01-02集_剧本.md含项目资料、当前批正文与后续节奏；单集按实际集号命名。只要替换段则交局部.md，不额外重交整批。聊天可展示节选，但有文件工具时不能只发聊天文本；不能写文件时交Markdown全文并说明未落盘。分文件仅按用户需要，且不能造成栏目缺失或突破批次限制。当前主稿与[精简接续](../SKILL.md#每次最多2集与上下文接续)分开，接续不是对外的后续故事节奏。

Markdown使用用户指定的加粗标签“**项目类型：**”“**一句话介绍：**”“**项目梗概：**”“**人物小传：**”“**后续故事情节节奏：**”，并留正常段落间距。人物小传写自然段，场景与对白按上述格式，不塞进长表格。附件Word只提供结构参照，不触发DOCX/PDF导出。

附件原始版式的实测记录仅作参考资料保留：A4竖版，上下页边距2.54cm、左右3.175cm；宋体，剧名12pt加粗居中、集标题14pt加粗居中、场头11pt加粗左对齐、正文11pt，1.5倍行距，段后0，无首行及左右缩进。附件为自然段、无表格、无强制每集分页。Markdown不伪称能固定实现这些Word版式参数。

## 交付前检查

从实际稿检查五项是否写实、位置是否正确、人物/梗概/正文/后续是否一致，以及本批集数、完整场景、知情连续、反转因果和对白时长。原书方法按project-delivery.md执行并留必要内部产物，不用空标题或编号声称已执行。[密度诊断](shortform-craft.md#静默容量诊断)内部进行，标准剧本不调用逐镜校验器。
